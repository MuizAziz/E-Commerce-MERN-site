1. What is Redux Toolkit?

Redux Toolkit React application ka shared data manage karta hai. Is mein data ek central store mein hota hai, jise different components easily access aur update kar sakte hain.
Example: E-commerce website mein cart ka data Navbar, Cart page aur Checkout page mein use ho sakta hai. Redux Toolkit is data ko centrally manage karta hai.
Why do we use it?
- To manage shared data between different components.
- To avoid prop drilling.
- To access and update data easily from different components.
Real-life Example:

In an E-commerce website:
- Navbar needs cart item count.
- Cart page needs cart products.
- Checkout page needs product prices.
Redux Toolkit stores cart data centrally so all these components can access it.
Important Terminologies
1. Store: Central place where application state is stored.
2. Slice: A particular section of the store, e.g., cartSlice, userSlice.
3. Actions: Operations we want to perform, e.g., addToCart, removeFromCart.
4. Reducers: Functions that define how state will be updated.
5. Dispatch: Used to send an action to Redux.
6. useSelector: Used to read data from the Redux store.
7. useDispatch: Hook used to dispatch actions.

3.What is bcrypt JS?

Bcrypt.js is a JavaScript library used in Node.js to securely hash passwords before storing them in the database.
Example:
Suppose a user registers with this password:
password: "123456"

Bcrypt converts it into a hashed value, something like:
$2b$10$randomHashedPassword...

This hashed password is stored in MongoDB instead of the original password.
Important Methods
1. bcrypt.hash() – Converts a plain password into a hashed password.
2. bcrypt.compare() – Checks whether the entered password matches the stored hash.
Working Flow
Registration: User Password → bcrypt.hash() → Hashed Password → MongoDB
Login:Entered Password + Stored Hash → bcrypt.compare() → Match or Not Match

15. Why do we need authContext.jsx?
Imagine a user logs into ShopNest.

After login, your application needs to know:
- Who is logged in?
- Is the user an admin or a normal customer?
- Should the Navbar show Login or Logout?
- Should the user be allowed to open the Admin Dashboard?
- What should happen when the user logs out?
Now imagine your application has 20 different components, and all of them need information about the logged-in user.

One solution is to pass user data through props, but this becomes difficult.

Context API solves this problem.

It allows you to share data with multiple components without manually passing props through every component.
